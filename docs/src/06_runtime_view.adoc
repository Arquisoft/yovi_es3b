== Runtime View

=== Single Player Game Initialization

**Diagram**

[plantuml,"Game Initialization Sequence with Difficulty",png]
----
actor User #87CEFA
participant "Web App" as Web #87CEFA
participant "Users Service" as Users #87CEFA
participant "Game Engine (Gamey)" as Gamey #87CEFA
participant "Bot (ybot)" as Bot #87CEFA

User -> Web: Open app / Join game

Web -> Users: Validate session token (JWT)
Users -> Users: Validate JWT\nExtract user identity
Users --> Web: 200 OK — user confirmed

Web --> User: Prompt to select difficulty
User -> Web: Select difficulty (easy/medium/hard)

Web -> Gamey: POST /gamey/new\nAuthorization: Bearer <JWT>\n{ player_id, difficulty }

Gamey -> Gamey: Validate JWT\nValidate difficulty\nCreate game\nAssign bot_id

Gamey -> Bot: POST /v1/ybot/init/{bot_id}\n{ player_id, difficulty }

Bot -> Bot: Load config\nInitialize state
Bot --> Gamey: 200 OK — ready

Gamey --> Web: 201 Created\n{ game_id, initial_board, status }

Web --> User: Render initial board
----

**Description**

The user opens the Web App and starts a game.  
The Web App sends the JWT to the Users Service, which verifies it using Firebase Authentication.  
Firebase validates the token and returns the user identity, which is forwarded back to the Web App.

The user selects a difficulty level, and the Web App sends a request to Gamey to create a new game.

Gamey validates the JWT again through the Users Service (which delegates verification to Firebase).  
Once validated, Gamey creates the game, assigns a bot based on difficulty, and initializes it.

The Bot prepares its internal state and confirms readiness.  
Finally, Gamey returns the initial game state and the Web App renders the board.

=== Player Move and Bot Response

**Diagram**

[plantuml,"Player move sequence (Web App → Gamey → ybot)",png]
----
actor User #87CEFA
participant "Web App" as Web #87CEFA
participant "Game Engine (Gamey)" as Gamey #87CEFA
participant "Bot (ybot)" as Bot #87CEFA

User -> Web: Make a move

Web -> Gamey: POST /v1/gamey/choose/{bot_id}\n{ YEN }

Gamey -> Gamey: Validate game state\nApply player move (Movement::Placement)\nCheck game over condition

Gamey -> Bot: POST /v1/ybot/choose/{bot_id}\n{ YEN }

Bot -> Bot: Parse YEN\nCompute best move (choose_move)\nReturn coordinates

Bot --> Gamey: MoveResponse { coords, status }

Gamey -> Gamey: Apply bot move\nUpdate internal board\nCheck win condition

Gamey --> Web: 200 OK\n{ coords, status, updated board }

Web --> User: Render updated board
----

**Description**

The user performs a move in the Web App.  
The request is sent to Gamey along with the JWT.

Gamey validates the token via the Users Service, which in turn uses Firebase Authentication.  
Once validated, Gamey processes the move, updates the board, and forwards the state to the Bot.

The Bot computes its move and returns it.  
Gamey applies the bot move, checks for win conditions, and persists the updated state.

The updated board is returned to the Web App and rendered to the user.


=== View Match History

**Diagram**

[plantuml,"Match history sequence (Web App → Users Module)",png]
----
actor User #87CEFA
participant "Web App" as Web #87CEFA
participant "Users Service" as Users #87CEFA
participant "Database" as DB #87CEFA

User -> Web: Click "History"

Web -> Users: GET /users/history\nAuthorization: Bearer <JWT>

Users -> Users: Validate JWT\nExtract user_id

Users -> DB: Query matches by user_id\nSort by date DESC

DB --> Users: Match list

Users --> Web: 200 OK\n{ match_history }

Web --> User: Display match history
----

**Description**

The user requests their match history from the Web App.  
The Web App sends the request to the Users Service with the JWT.

The Users Service validates the token using Firebase Authentication and extracts the user_id.  
It then queries the database for matches associated with that user.

The results are returned to the Web App, which displays them to the user.
